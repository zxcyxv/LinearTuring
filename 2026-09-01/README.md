## 1. 세그먼트 외삽 (`analysis/seg_extrap.py`)

학습은 16 세그먼트(`loops=16`, `blocks_per_seg=8`). 가중치를 건드리지 않고 추론에서 세그먼트만 더 준다.
채점은 학습 하네스(`refs/URM/models/losses.py`)와 같은 정의: `accuracy` = 81칸 중 맞은 비율,
`exact` = 81칸 전부 맞은 퍼즐 수, `churn` = 직전 세그먼트 대비 답이 바뀐 칸 비율.
가중치는 `model_state_dict`(= EMA 적용본, `ema_shadow` 와 비트 동일함을 확인), 버퍼(`init_hidden`,
`puzzle_emb.weights`)는 `raw_model_state_dict` 에서.

## 2. HRM 공식 체크포인트 직접 측정 (`analysis/seg_extrap_hrm.py`)

`sapientinc/HRM-checkpoint-sudoku-extreme` 의 `all_config.yaml` 이 `data_path: data/sudoku-extreme-1k-aug-1000`,
`halt_max_steps: 16` — **우리와 같은 데이터셋·같은 학습 세그먼트**다. 빌드 스크립트상 test 는 증강도 서브샘플링도
없으므로 테스트 2,048 도 동일하다. ACT 는 끔(`act_inference=False`, URM 포크의 추론 기본값) — 결정론적 스윕.

측정 신뢰도: 우리가 잰 HRM seg16 = **54.10%**, 논문 보고치 **55.0%**. 0.9%p 차이.

주의: HRM 논문 Fig 5(c) 의 추론시간 스케일링은 **Sudoku-Extreme-Full (3,831,994 예제)** 에서 잰 것이고
(캡션 `:568`, 본문 `:687-690`), 헤드라인 55.0% 는 1,000 예제 설정이다. **1k 어려운 영역의 외삽은 보고된 적이 없다.**
테스트셋은 90/10 분할의 같은 10% 이므로 두 수치의 격차는 순수하게 학습 데이터 양의 효과다.

## 5. w 의 구조 (`analysis/w_rank.py`, `analysis/w_diag.py`)

`w` 는 `[B,H,T,T]` — 퍼즐마다·헤드마다 81×81 행렬, 칸의 순서쌍마다 실수 하나. 파라미터가 아니라 인스턴스 상태이며
세그먼트 경계에서 `coupling=w.detach()` 로 값만 넘어간다.

- **랭크가 정확도·churn 과 같은 지점(seg 96)에서 동시에 포화한다.** w 참여비 45.24 → 72.27 (상한 81), a 는 26.79 → 41.40.
- **그 랭크의 대부분은 대각이다.** 대각 에너지 비중 55.6%(seg1) → 81.7%(seg32). 비대각의 **안정랭크는 6~7.6** 뿐이고
  크기는 0.0455 → 0.0210 으로 오히려 줄어든다.
- **대각은 칸에 대해 상수다** — 변동계수 **1.2%** (헤드 간에는 15%). 사실상 헤드당 스칼라.
- **정답을 고르지 않는다** — 최종 정답 칸과 오답 칸의 대각 평균 차이가 seg192 에서 **+0.001σ**, 중간에도 −0.23σ 이내
  (부호는 오히려 오답 쪽이 큼). 헤드별 상관 최대 |r| = 0.211.
- 구조상 그럴 수밖에 없다: `a_tt = Σ_j r_tj²·cos(ψ_j)` 이고 `Σ_j r_tj² = 1` (주소 정규화) 이므로 cos 의 가중평균이다.

**커널 대각과 기억 대각의 부호가 반대다**: `a_tt = −0.4582`, `w_tt = +0.6618`.
λ=0.305 에서 `a_eff,tt = 0.695×(−0.458) + 0.305×(+0.662) = −0.116`.
즉 이 모델은 원래 자기 자신을 밀어내고(내장 반고착), **기억이 하는 일은 강화가 아니라 그 반발의 상쇄다.**

## 6. 대각 절제 — 정지와 정확도의 분리

`core/minimal.py` 에 `stdp_diag: keep|zero|only` 추가 (기본 `keep`, 무변경 검증 완료: seg16 완답 1043 동일).
`Γ` 단계에서 걸러 `w` 대각이 항상 0(또는 대각만)이 되게 한다.

| 조건 | `a_eff,tt` | seg16 | 최고 | Δ | churn 16→256 |
|---|---:|---:|---:|---:|---|
| 원본 `keep` | −0.116 | 50.93% | 77.49% | **+26.56%p** | 0.0695 → **0.00039** (177배) |
| `zero` (자기시냅스 제거) | −0.318 | 0.00% | 0.00% | 0.00%p | 0.2906 → 0.5900 (**발산**) |
| **`only`** (관계항 제거) | −0.116 | 22.22% | 22.90% | **+0.68%p** | 0.00955 → **0.00032** (30배) |
| `lam=0` (기억 전체 제거) | −0.458 | 0.00% | 0.00% | 0.00%p | 0.6750 → 0.6671 (없음) |

**`only` 이 결정적이다. 멈추는데 못 푼다.** churn 이 원본의 바닥(0.00039)과 사실상 같은 0.00032 에 도달하고,
게다가 seg16 에서 이미 0.0096 으로 원본(0.0695)보다 7배 조용하다. 그런데 완답은 22.22% → 22.90%, Δ=+0.68%p.

> **대각(자기결합) = 제동장치.** 내장 자기반발을 상쇄한다. 없애면 발산, 이것만 있으면 즉시(틀린 답에) 얼어붙는다.
> **비대각(관계 STDP 기억) = 엔진.** 상태를 해답 쪽으로 움직인다.
> **+26.56%p 는 둘의 상호작용이다.** 제동만 +0.68%p, 제동 없으면 0, 둘 다 있어야 +26.56%p.

부수: `lam=0`(0%, churn 0.67)에 자기결합 스칼라 하나만 더하면 22.9% 가 된다.

주의: `zero` 와 `lam=0` 은 둘 다 0% 라 "분포 밖이라 무너진 것"과 구별되지 않는다. 반면 `only` 는 자기결합을
원본과 정확히 같게 유지한 채 관계항만 뺐는데 붕괴하지 않고 일관된 고정점(22.9%)을 만들었으므로 신호가 신뢰된다.

**남은 것**: STDP 에 자기시냅스(autapse)는 없으므로 원론적으로는 `Γ` 에서 대각을 빼고 **명시적 자기결합
파라미터 `s_h [H,1,1]`** 로 대체해 학습하는 것이 맞다 (`a_eff = (1−λ)a + λ·w_offdiag + s_h·I`).
그러면 ψ=라우팅 / s_h=제동 / w=관계 기억 으로 세 축이 분리되고, λ 가 두 몫을 겸하는 타협이 풀린다.
`w_tt` 가 seg 8 이후 상수(0.662)이므로 "확신이 커질수록 굳는다"는 담금질은 원래 없었고, 분리로 잃을 것이 없다.
다만 `a_tn` 계산 자체에는 t=n 이 있어야 하므로 어디까지 빼는지는 별도 결정. **미실행.**

## 7. 테스트셋 유출 점검 (`analysis/leak_check.py`)

빌드 스크립트상 train/test 는 sudoku-extreme 의 서로 다른 CSV 이고 증강은 train 에만 걸린다
(`num_augments = num_aug if set_name == "train" else 0`). 실제 파일에서 확인: 학습 1,001,000 행 vs 테스트 2,048 행.

| 점검 | 결과 |
|---|---|
| 테스트 문제 ∩ 학습 문제 (증강 포함) | **0** |
| 테스트 (문제, 정답) ∩ 학습 (문제, 정답) | **0** |
| 테스트 정답판 ∩ 학습 정답판 | **0** |
| 증강군 궤도 동치 (자릿수 9! × 전치 2 × 밴드 1296 × 스택 1296) | 서명 충돌 58쌍 → 전수 검증 **실제 동치 0** |
| 퍼즐 식별자 | train·test 모두 `0` 하나 (`num_puzzle_identifiers=1`) — 임베딩 통로 없음 |

**유출 없음.** HRM 논문도 같은 취지로 적고 있다 (`:686`): *"a strict 90/10 train-test split, ensuring that the
test set puzzles cannot be derived through equivalent transformations of any training samples."*
